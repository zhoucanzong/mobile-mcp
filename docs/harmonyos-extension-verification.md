# 鸿蒙功能扩展验证记录

本轮范围为拖拽、双指缩放、组合手势，以及等待、操作结果检查、失败截图与日志、条件分支、循环和显式重试。沿用已确认的阶段边界：先实现并以模拟路径验证，所有真机测试集中留到连接 Mate 60 Pro 后执行。

## 逐项证据

| 要求 | 实现与验证 | 当前结论 |
|---|---|---|
| 拖拽 | `harmony-gestures.ts` 的触屏 hold+move 参数；测试验证单命令、总时长及按住时长 | 源码和模拟路径通过，待设备响应验证 |
| 双指缩放 | 同一 uinput 调用传递两条触屏轨迹；测试检查向内、向外、竖直及两指参数 | 未用顺序滑动代替双指；真机待验证 |
| 组合手势 | `HarmonyRobot.performGestures`；测试验证顺序、全部坐标预检查、失败即停和时长上限 | 手势间抬指，不宣称连续任意轨迹 |
| 等待元素 | Unicode 条件、存在/消失、稳定时间；测试覆盖出现、抖动、超时及读取失败 | 不把读取异常当作元素消失 |
| 操作结果检查 | assert 工具、workflow 的 expect；测试证明已执行操作仍可因结果不符失败 | 成功取决于明确条件，不只看命令返回 |
| 失败截图和日志 | 私有临时目录、实际 PNG/JPEG、日志、报告；测试读取实际保存文件及权限 | 取证项目分别记录失败，不覆盖原始错误 |
| 条件与循环 | if/else、固定次数 repeat、until 提前退出及次数用尽报错 | 模拟执行及 MCP 协议测试通过 |
| 显式重试 | 默认一次、最多三次，每次重新定位；失败尝试保留在历史中 | 不自动重复动作，不提供回滚 |
| 执行边界 | 声明与执行节点上限、嵌套层数、设备固定、允许工具列表、超时 | 测试覆盖越界、禁止嵌套工作流、跨设备及云工具 |
| 文档同步 | 中/英/日 README、鸿蒙功能表、`automation.md` 参数与示例 | 从实际 MCP 工具列表核对 41 个工具，四份索引无漏项 |

## 本地验证

- `npm run build`：通过。
- `npm run lint`：通过。
- `npm test`：286 项通过，其中新增 37 项测试；不包含任何真机验收结论。
- 新增测试位于 `test/harmony-gestures.test.ts`、`test/automation.test.ts`、`test/server-automation.test.ts`，已有工具描述和注解测试同时覆盖新工具。
- `git diff --check`：通过。
- 原生录屏、定位源码在本轮未修改。分支 CI 仍运行既有两组原生生命周期测试，具体提交结果见仓库 Actions。

## 保留边界

- uinput 帮助和参数回显不能证明商业手机已授权注入，也不能证明应用产生预期 UI 变化。
- 总期限在设备调用之间检查，不能强行打断已经发出的设备命令。失败取证有额外耗时。
- 多客户端操作同一设备没有隔离，需协调使用；屏幕检查也不是系统级原子快照。
- 录屏、剪贴板和系统定位的既有权限条件继续有效，未因本轮扩展得到真机验证。
- [扩展使用说明](automation.md#第二阶段统一真机验收)给出了统一真机验收清单。
